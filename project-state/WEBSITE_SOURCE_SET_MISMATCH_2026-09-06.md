## Control determination

The exact master-versus-jurisdiction ID delta is generated by `scripts/verify_website_source_sync.py` and is preserved as a workflow control artifact.

## Website source-set decision

The production website uses a controlled jurisdiction-ledger fallback. Master-ledger rows remain labelled `Master ledger`. Rows present in a jurisdiction-specific substantive source ledger but absent from the master are labelled `Jurisdiction-ledger fallback`. The fallback does not constitute master-ledger integration.

A completed jurisdiction with neither master rows nor a controlled local-ledger fallback is a build failure. Silent empty source-set publication is prohibited.

## Public-content decision

The public build validates generated HTML against project-control filenames and project-management instructions. The identified `DECISIONS_LOG.md` reference is sanitized in generated output by `scripts/sanitize_public_html.py`. The substantive research source is not changed by this sanitizer.

## Implementation

- `scripts/verify_website_source_sync.py` performs the deterministic source-ID comparison.
- `scripts/build_website_v2.py` is the production builder for the Pages workflow and implements master/fallback provenance.
- `scripts/sanitize_public_html.py` removes the identified project-control filename from generated public HTML.
- `.github/workflows/pages.yml` compiles the controls, runs the source-ID comparison, preserves its exact output as a workflow artifact, builds the site, sanitizes the identified leakage, rejects empty source pages and rejects project-control leakage.
- The legacy `scripts/build_website.py` remains in the repository because its direct replacement operation through the repository connector returned a SHA conflict. It is not the production builder used by Pages after this remediation.
