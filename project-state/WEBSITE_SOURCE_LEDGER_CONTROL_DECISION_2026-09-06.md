# Website Source-Ledger Control Decision

Date: 2026-09-06
Phase: 1
Workstream: website/source-ledger synchronization control only
Status: IMPLEMENTATION AUTHORIZED

## Control question

The public source-set layer must represent the completed jurisdiction research records without silently treating jurisdiction-specific source-ledger rows as integrated into the master ledger.

## Decision

The public website will use a controlled two-tier source rule:

1. `research/STATE_IMPLEMENTATION_SOURCE_LEDGER.md` remains the master source ledger and is authoritative for rows actually integrated into that ledger.
2. When a completed jurisdiction research record references source IDs that are absent from the master ledger, the website may use the corresponding substantive `research/states/*_SOURCE_LEDGER.md` as a controlled jurisdiction-ledger fallback for public source rendering.
3. Fallback rows must remain explicitly identified as jurisdiction-ledger fallback rows. The website must not describe them as master-ledger rows or imply that master-ledger integration has occurred.
4. The substantive master ledger is not modified as part of this website remediation.
5. The source-set build must fail or visibly flag a completed jurisdiction with neither master rows nor a controlled jurisdiction-ledger fallback. Silent empty source-set publication is prohibited.
6. The build must report the exact source-ID set present in jurisdiction-specific ledgers but absent from the master ledger. This comparison is a control comparison, not a substantive source search.

## Rationale

The jurisdiction-specific ledgers are substantive repository records. The master-ledger gap is a repository control/integration defect, not evidence that the underlying source records do not exist. A controlled fallback preserves public traceability while maintaining the distinction between master integration and jurisdiction-specific source records.

A master-ledger-only website would continue publishing empty source-set pages and would misrepresent the available repository evidence. Silent fallback without provenance would create a different control defect. The selected rule avoids both errors.

## Validation requirements

The website build must validate:

- every completed jurisdiction has a non-empty controlled source set unless an explicit controlled absence exists;
- master rows and fallback rows are distinguishable;
- the exact master-versus-jurisdiction-ledger ID gap is reported;
- generated HTML contains no project-control filenames or project-management instructions;
- the identified `DECISIONS_LOG.md` leakage is absent;
- existing repository-navigation-link validation remains active.

## Scope boundary

This decision does not reopen substantive State/UT research, does not alter any source finding, does not integrate the master ledger, and does not authorize Ladakh, Lakshadweep or Puducherry research. It does not authorize Bill drafting, policy-superiority/necessity analysis, constitutional-validity analysis or Phase 2 case-law research.

## Exact-gap status

The exact source-ID delta is to be generated by the deterministic repository comparison implemented in `scripts/verify_website_source_sync.py`. It must be recorded after the first post-decision control run. No substantive source search is required or authorized.
