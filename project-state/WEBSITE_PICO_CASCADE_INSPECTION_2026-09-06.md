# Website Pico Theme Cascade Inspection

Date: 2026-09-06

## Inspection result

`website/assets/pico-theme.css` is a controlled candidate layer and is not production-integrated.

The existing production cascade is led by `website/assets/site.css`, with `.github/workflows/pages.yml` appending `website/assets/site-overrides.css` to the generated `site.css` during the Pages build. `scripts/build_website_v2.py` currently links only `assets/site.css` in the generated HTML.

The existing site stylesheet defines its own global typography, layout, controls, cards, tables, navigation, responsive breakpoints, colours and focus-visible rules. Pico 2.1.1 also supplies global element defaults and variables. Loading Pico after the production stylesheet would therefore risk overriding the established production cascade. Loading Pico before `site.css` is the safer controlled integration order because the existing site CSS remains the primary visual layer and the override sheet remains last.

## Integration decision

Pico integration is NOT yet declared deployed.

The correct builder change is to add the Pico stylesheet before `site.css` in the HTML shell generated by `scripts/build_website_v2.py`, with a versioned cache key on the local candidate asset. The integration must then be followed by the complete static website audit and a new Pages artifact verification.

No Pages deployment claim is made from this inspection. No generated Pages artifact was produced by this inspection alone.

## Scope protection

Do not replace the existing site design wholesale with Pico defaults. Treat Pico as a controlled base/theme layer. Preserve existing navigation, cards, tables, responsive behaviour, focus-visible controls, accessibility checks and generated route structure unless the post-integration audit identifies a defect.
